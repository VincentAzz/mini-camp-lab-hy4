## 2. 额度恢复后本轮的修复

### 2.1 车轮方向异常（用户指出，最高优先级）

**根因**：`common/PropsLibrary.ts` 的 `wheel()` 把 `CylinderGeometry`（轴向 Y）绕 **Z** 轴旋转 90°，使轮盘平面落在 Y-Z、法线沿 X，与车体侧面垂直 —— 从默认相机所在的 +Z 侧看过去只是一条竖线。正确做法是绕 **X** 轴旋转 90°，让轮盘平面落在 X-Y、法线沿 Z，轮宽沿 Z。

| 位置 | 修复 |
| --- | --- |
| `common/PropsLibrary.ts` `wheel()` | 胎与轮毂 `rotation.z = π/2` → `rotation.x = π/2`（一处修复，覆盖 5 款车全部行驶轮） |
| `vehicles/overland/index.ts` | 每个轮子的 8 个全地形胎纹小节从 Y-Z 圆周改到 X-Y 圆周，厚度沿 Z 覆盖轮宽，避免胎纹飘出轮面 |
| `vehicles/typeC/index.ts`、`vehicles/trailer/index.ts` | 挂在车尾的备胎由「躺平轮胎」`tire()` 改为 `wheel()` + `rotation.y = π/2`（法线沿 X，正对车尾） |
| `scenes/wasteland/index.ts` | 汽车残骸的 4 个车轮改用 `wheel()` 竖立；轮胎堆去掉多余的 `rotation.x = π/2`，并把层距改为 0.38（大于轮胎厚度），消除叠放互相穿插 |
| `vehicles/overland/index.ts` 货斗备胎 | 保留平放（平放备胎是合理摆放，且下沿贴合货斗地板） |

**验证方式**：在运行时审计中新增**车轮朝向专项校验** —— 构造 `lib.wheel(0.42, 0.22)`，用 `contentBox()` 取真实包围盒，要求 `X ≈ Y ≈ 2r` 且 `Z ≈ 轮宽`；若绕错轴会变成 `X ≈ w`、`Z ≈ 2r`。最终回传结果为 `wheelIssues: []`。

### 2.2 遮阳棚悬空（同一类视觉断裂，顺带系统修复）

C 型、van、trailer 的棚布原本只铺在两根立柱之间，与车身 +Z 面之间空出 0.85~1.2 的缝隙。统一加深棚布深度并把中心内移，使内边缘贴到车身面、外边缘延伸到立柱：

- `typeC`：`cloth(2.60, 1.20)` @ z=3.00 → `cloth(2.60, 2.42)` @ z=2.41（覆盖 1.20~3.62）
- `van`：`cloth(3.00, 1.30)` @ z=2.95 → `cloth(3.00, 2.42)` @ z=2.37（覆盖 1.16~3.58）
- `trailer`：`cloth(3.5, 1.25)` @ z=2.72 → `cloth(3.5, 2.15)` @ z=2.30（覆盖 1.23~3.38）
- `typeA`：在此前受控增强中已修（1.27~3.73 连续），保持不变
- `overland`：为竖直侧遮阳幕（挂在独立横杆下），不属于水平棚布，保持不变

## 6. 运行与校验命令

```bash
pnpm install
pnpm dev                  # 本地 Vite，127.0.0.1:5173（用内置预览打开）
pnpm build                # tsc --noEmit + vite build → dist/
pnpm typecheck
pnpm validate:layout      # 静态布局 / 穿模校验
pnpm validate:contracts   # 模块契约与注册表自动装配校验
```
