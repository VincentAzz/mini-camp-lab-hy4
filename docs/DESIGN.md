## 1. 需求理解与要点清单（对照提示词逐节归纳）

### 1.0 一句话理解

一个**纯前端、零运行时网络依赖**的三渲二微缩景观盒：以第三视角环绕观察，通过轻量 UI 在 **4 场景 × 5 车型 × 4 时间 × 5 天气 = 400 种组合**中自由巡游；默认第一眼是「海崖 · C型房车 · 黄昏 · 晴朗」。所有几何体与贴图必须用代码程序化生成，禁用任何 DCC 与外部建模软件；整体气质是安静、治愈、带旅途黄昏辽阔孤独感却依然温暖的日式动画定格一幕。

**关键推论（决定架构）**：400 组合是**正交**的，绝不能为某个组合硬编码一套场景内容。必须由四个维度各自贡献「光照 / 装饰 / 粒子 / 材质」增量，再由统一的合成器叠加。这也是提示词 2.5、3.6、8.4 反复强调注册表与模块化的根本原因。

### 1.1 第一节 · 整体形式与美术总纲

| --- | --- | --- | --- |

### 1.2 第二节 · 场景系统（首发 4 个，架构可扩展）

- **解耦硬要求**：场景与车型、时间、天气完全解耦；任何车辆可停在任一场景的中央营位；任一场景可在任意时间与天气下观看。
- **场景构成公式**：正方形底座 + 环境元素 + 场景专属动效 + 场景专属色彩基调（再被时间/天气系统调制）。
- 各场景要点（详细元素清单见 §4.1）：

| 场景 | 地形构图 | 色彩基调 | 专属动效（摘要） |
| --- | --- | --- | --- |
| 2.1 海崖营地（默认） | 悬崖草坪临崖营位，车辆居视觉中心，明确的「临崖观海」构图，夏末旅行一幕 | 日落金橙 × 海面蓝紫渐变、粼粼波光、晚霞；黄昏时暖车内灯 × 冷暮色海景的强冷暖对比 | 串灯闪烁、天幕摆动、波光流动、灯塔光束旋转、海鸟掠过、夜灯呼吸、纸巾被风掀 |
| 2.2 山间松林营地 | 高大层叠松林环抱的林间空地碎石营位，松树高低错落、树冠层叠 | 森林绿 × 晨雾青白，光斑与雾气随时间变化；强调「林间静谧」 | 松针摆动、光斑摇曳、溪流与落叶、松鼠窜过、吊床轻晃、篝火火星、晨雾流动 |
| 2.3 末日避难所营地 | 废土上被加固的营地，车辆在硬化地面视觉中心，工事与围墙半包围 | 锈红 × 沙黄 × 混凝土灰，点缀火光与冷色荧光；「废土据点」，干净画风的治愈系末世 | 探照灯扫动、警示红灯旋转、天线灯闪、发电机蒸汽、火堆火星、衣物飘动、光柱微尘 |
| 2.4 高速路服务区 | 带划线车位的一角，车辆停在视觉中心的房车专用大车位 | 柏油灰 + 便利店暖光 + 行道树绿；夜间以灯箱/售货机/车流灯光为主角；「旅途驿站」「道の驿」 | 车流灯光流动、招牌微闪、售货机灯带、小旗飘动、树叶轻摆 |

- **2.5 硬性架构要求**：场景以注册表 / 模块化实现。每个场景是独立模块，包含**地形、道具布置、场景动效、色彩基调、光照钩子**；在场景注册表登记即可被 UI 与切换逻辑识别。**新增场景不应修改核心渲染与切换代码，只需新增模块并注册。** 详见 §3.3、§3.5。

### 1.3 第三节 · 车型系统（首发 5 种，架构可扩展）

- **两个所有车型必须保留的核心特征**：① 外拓展机构已展开；② 内部可透过车窗 / 帐帘**清楚看到**。
- **差异化硬要求**：不同车型的展开方式、涂装与内饰风格必须有明显差异；**细节量不得少于 C 型房车**。
- 允许轻微适配（接地高度、朝向、末世场景蒙尘涂装等，不强制）。
- 车型要点（详见 §4.2）：

| 车型 | 外部 / 展开 | 透视内饰要点 | 气质差异 |
| --- | --- | --- | --- |
| 3.1 C型房车（默认） | 升顶展开、侧拓展舱滑出、经典凸头驾驶舱 | 驾驶舱大屏仪表、卡座餐桌、厨房水槽灶台、冰箱、吊柜、床铺小夜灯、拓展舱内沙发书架 | 明亮温暖真实充实的紧凑旅居感；黄昏时与冷暮色海天形成强冷暖对比 |
| 3.2 A型大巴式房车 | 方正大巴车身、大前挡与贯通侧窗、车顶空调外机与卫星锅、侧裙储物舱门、侧遮阳棚 + 电动踏步、车尾自行车架 | 环形豪华沙发卡座、中岛厨房（双开门冰箱/水槽/嵌灶/烤箱）、通顶吊柜与暖色灯带、木纹地板、半隔断独立卧室双人床、小卫浴（洗手盆+淋浴隔断） | 「移动小公寓」暖木色豪华感，与 C 型紧凑温馨形成对比 |
| 3.3 拖挂式房车 + 牵引皮卡 | 全尺寸皮卡（货斗行李箱/备用油桶/柴火）牵引流线型白色拖挂；支撑腿放下、遮阳棚展开、前部燃气瓶与备胎可见；拖挂两侧大窗可透视 | 尾部横置双人床与舷窗、紧凑厨房吊柜、对坐卡座与可升降桌板、小卫生间隔断；皮卡双排舱内仪表盘/中控屏/后座睡袋行李 | 「车队式」旅居感 |
| 3.4 B型露营面包车（vanlife） | 圆润复古双色车身、车顶行李架捆冲浪板、侧遮阳棚、后掀尾门与纱帘、手绘小贴纸；大侧窗与掀顶帐帘透视 | 对坐小卡座 + 翻折小桌（可变床结构做半展开展示）、迷你厨房（单孔灶/小水槽/迷你冰箱）、车内串灯、挂毯小盆栽、手冲咖啡具与散落的书 | 慵懒随性「自由职业者在路上」 |
| 3.5 越野皮卡 + 车顶帐篷（overlanding） | 升高底盘 + 全地形胎、车顶折叠帐篷已展开（登车梯 + 边 LED 灯串）、侧遮阳幕、货斗油桶/水箱/工具箱/折叠桌板、车侧爬梯与车顶探照灯；双排车窗透视 | 全液晶仪表与中控大屏、后座改装休憩区（睡袋、摊开的地图、手持对讲机、杂物网兜） | 硬朗但整洁「远征装备控」细节感 |

- **3.6 硬性架构要求**：车型注册表 / 模块化。每个车型模块声明**外部模型、展开机构、透视内饰、内饰灯光钩子**四项。新增车型 = 新增模块并注册，不修改核心逻辑。

### 1.4 第四节 · 时间系统（清晨 / 白天 / 黄昏 / 夜间）

- **解耦硬要求**：每个场景都必须**完整实现四种时间**；切换时间时灯光、天空、阴影**与装饰物状态**都要变化，**不允许只换色调不换内容**。
- 四时段要点：

| 时段 | 通用表现 | 各场景专属表现（必须逐条落地） |
| --- | --- | --- |
| 清晨 | 低角度青金色晨光、薄雾、长投影；营地灯将熄未熄、篝火只剩余烬、桌上出现早餐餐具、晾晒物带露水高光 | 海崖：朝霞 + 刚刚出海的小帆船；松林：流动晨雾 + 鸟鸣般的光斑跳动；服务区：刚开灯的便利店 + 送货小车；避难所：刚换岗扫动的探照灯 |
| 白天 | 明亮柔和正午光、干净饱和色彩、短而清晰阴影；灯具全熄、天幕与遮阳棚投影清晰；出现炊烟、蒸汽等「白天活动」细节 | 四场景均以明亮基准 + 场景自身活动细节呈现 |
| 黄昏（默认） | 保留原始核心氛围：日落金橙 × 海面蓝紫渐变、晚霞、蓝调时刻、暖车内灯 × 冷暮色海景强对比 | 海崖：串灯点亮、灯塔开始工作；松林：逆光剪影 + 金色光斑；服务区：招牌灯箱初亮、车流渐密；避难所：探照灯与警示灯启动 |
| 夜间 | 月光与星空主导，环境深蓝紫；所有灯光道具点亮并带柔和光晕（串灯、营地灯、车内灯、灯塔光束、便利店灯箱、售货机灯带、探照灯、警示红灯）；车内暖光更突出，成为深夜温暖焦点 | 四场景灯光组按各自道具集全部启用 |
| 实现 | 「光照预设 + 装饰物状态切换」；切换有 **1~2 秒平滑光照过渡（交叉淡入淡出）**，不生硬跳变 | §4.3、§5.6 |

### 1.5 第五节 · 天气系统（晴朗 / 多云 / 小雨 / 浓雾 / 降雪）

- **解耦硬要求**：任意组合均有效，提示词举例「夜间小雨的末日避难所」「清晨浓雾的山间松林」「黄昏降雪的海崖」。天气影响**光照强度、粒子效果、材质状态**。

| 天气 | 要点 |
| --- | --- |
| 晴朗（默认） | 各场景基准表现 |
| 多云 | 云量增加、光照柔化、云影在地面缓慢移动、风力略增 |
| 小雨 | 雨丝粒子、地面湿润反光与水洼涟漪、天幕/遮阳棚布料因积水微微下凹、屋檐滴水；夜间灯光在湿地面拉出彩色反光 |
| 浓雾 | 远景逐层雾化、灯光产生扩散光晕、景深层次被压缩，静谧朦胧 |
| 降雪 | 雪花缓慢飘落、屋顶/天幕/树枝/护栏/桌椅顶部积雪、地面覆薄雪（服务区车位划线若隐若现） |
| 实现 | 天气粒子与材质状态切换同样**平滑过渡**；天气与时间叠加取**综合光照**（如夜间浓雾 = 更暗 + 更强光晕） |

### 1.7 第七节 · 动效要求（「静止但活着」）

- 整体是静止精致的微缩世界，但有恰到好处的细微动态；四场景专属清单见 §7。
- **通用系统**（7-5）：天气粒子（雨/雪）、灯光呼吸统一节奏；**布料类元素（天幕、吊床、挂毯、晾晒衣物、小旗）统一受风力参数控制，风力随天气变化**。

### 1.8 第八节 · 技术约束与工程要求

| # | 约束 | 落地 |
| --- | --- | --- |
| 8-1 | pnpm 为包管理器；建议 Vite + Three.js（TypeScript 优先）；纯浏览器运行，**运行时不依赖网络** | §2 技术选型 |

### 3.3 核心接口契约（`registry/types.ts` 草案）

```ts
export type SceneId   = 'seaCliff' | 'pineForest' | 'wasteland' | 'highwaySA';
export type VehicleId = 'typeC' | 'typeA' | 'trailer' | 'van' | 'overland';
export type TimeId    = 'dawn' | 'daytime' | 'dusk' | 'night';
export type WeatherId = 'clear' | 'cloudy' | 'rain' | 'fog' | 'snow';

export interface ComboState {
  scene: SceneId; vehicle: VehicleId; time: TimeId; weather: WeatherId;
}

/** 装饰物状态 API：时间与天气只通过它改变场景内容，不直接操作场景内部对象 */
export interface DecorAPI {
  setFlag(key: DecorKey, value: number): void;   // 0~1，支持渐变
  spawn(id: string): void;                       // 清晨小帆船、送货小车等
  despawn(id: string): void;
  setLightGroup(group: LightGroupKey, intensity: number): void;
}

/** 场景模块（2.5：地形 / 道具布置 / 场景动效 / 色彩基调 / 光照钩子） */
export interface SceneModule {
  id: SceneId; label: string; icon: string;
  palette: ScenePalette;                 // 场景专属色彩基调
  build(ctx: SceneContext): THREE.Group; // 只构建一次，结果缓存
  onTimeChange(next: TimeId, prev: TimeId, api: DecorAPI): void;   // 光照钩子 + 装饰
  onWeatherChange(next: WeatherId, api: DecorAPI): void;
  update(dt: number, elapsed: number, env: EnvSnapshot): void;      // 场景专属动效
  dispose(): void;
}

/** 车型模块（3.6：外部模型 / 展开机构 / 透视内饰 / 内饰灯光钩子） */
export interface VehicleModule {
  id: VehicleId; label: string; icon: string;
  exterior: (lib: PropsLibrary) => THREE.Group;
  deploy:   (lib: PropsLibrary) => THREE.Group;   // 已展开的拓展机构
  interior: (lib: PropsLibrary) => THREE.Group;   // 透视可见
  interiorLights: (api: DecorAPI) => LightSpec[]; // 内饰灯光钩子
  anchor: { groundOffset: number; yaw: number; scale: number }; // 轻微适配
  update?(dt: number, env: EnvSnapshot): void;
}

/** 时间预设（第四节：光照预设 + 装饰物状态切换） */
export interface TimePreset {
  id: TimeId; label: string; icon: string;
  light: { sun: DirLightSpec; ambient: AmbientSpec; hemi: HemiSpec; sky: SkySpec };
  tone:  { exposure: number; fog: FogSpec; shadowLength: number };
  decor: DecorFlags;                                  // 灯具/余烬/早餐/炊烟/招牌…
  sceneHooks: Partial<Record<SceneId, (api: DecorAPI) => void>>;  // 各场景专属表现
}

/** 天气模块（第五节：光照修正 / 粒子 / 材质状态 / 风力） */
export interface WeatherModule {
  id: WeatherId; label: string; icon: string;
  lightModifier: { intensity: number; ambientDelta: number;

  windScale: number;
  particles?: ParticleSpec;
  surface?: { wetness: number; snow: number; clothSag: number };
  build?(ctx: SceneContext): THREE.Object3D;
  update?(dt: number, env: EnvSnapshot): void;
  dispose?(): void;
}
```

### 3.4 400 组合的实现原理：正交增量合成

**单一数据源**：`Store` 持有 `ComboState`，任何切换都是 `Store.patch({...})` 派发，各系统订阅自己关心的字段。

**四类增量与优先级**（`LightingComposer` + `weathers/modifiers.ts`）：

```
时间  → 基准光照（太阳角度/色温/强度、天空渐变、雾、曝光）+ 装饰物状态（开关/出现消失）
天气  → 对基准的乘性 / 加性修正：
        final.sunIntensity = time.sun.intensity × weather.intensity
        final.ambient      = time.ambient + weather.ambientDelta
        final.fogDensity   = max(time.fog, weather.fogDensity) + nightFogBonus
        final.glow         = time.glow × weather.glow
        final.wind         = BASE_WIND × weather.windScale
        final.wetness/snow = weather.surface（写入全局 Shader Uniform）
场景  → 专属色彩基调 + 光照钩子 + 专属装饰状态覆盖（如灯塔、探照灯、招牌）
车型  → 内饰灯光（独立光组，不参与环境光合成，但受时间/天气的 glow 调制）
```

**冲突裁决**：时间给基准、天气给修正、场景给钩子覆盖、车型只管车内。任何组合都不需要专门代码，只靠这四条规则叠加。示例：

| 组合 | 合成结果 |
| --- | --- |
| 夜间 · 浓雾 · 松林 | 夜间基准（月光/星空/全灯点亮）+ 浓雾（更暗、更强光晕、远景逐层雾化、景深压缩）+ 松林晨雾模块按雾强度放大 |
| 黄昏 · 降雪 · 海崖 | 黄昏金橙晚霞 + 降雪粒子 + 屋顶/护栏/桌椅积雪 + 串灯暖光在雪面上的柔和反光 |
| 夜间 · 小雨 · 避难所 | 月光蓝紫 + 雨丝 + wetness 高反光 + 探照灯/警示红灯在湿地面拉出彩色反光 |

### 3.5 切换数据流

```
用户点击 UI
  → Store.patch(维度, 新值)
  → SwitchController 分类：
      ├─ 结构性（scene / vehicle）：淡出(0.2s) → dispose 旧子树 → build 新子树
      │     → 重新应用当前 time/weather → 淡入(0.3s)
      └─ 参数性（time / weather）：启动 1~2s 交叉淡入淡出插值
            → 光照 Uniform / 天空 / 雾 / 曝光 / 粒子密度 / 材质状态 / 装饰显隐全插值
  → 期间 camera 与 OrbitControls 的 spherical / target 完全不动（6-5）
  → 防抖：结构性切换进行中只保留最后一次请求，按钮置 loading 态
```

**扩展契约（硬性验收项）**：
- 新增场景：复制 `scenes/_template/` → 实现 `SceneModule` → 在 `sceneRegistry.ts` 加一行 `register(mod)` → UI 自动出现新按钮，切换逻辑自动识别。**核心层零改动**。
- 新增车型 / 时间 / 天气同理（各自注册表 + 模块目录）。
- UI 面板的按钮**由注册表遍历生成**，不允许手写按钮列表，否则扩展时会漏。

### 4.1 场景模块（逐场景）

**共性约定**

- `BasePlate`：固定边长的正方形底座（含厚度与倒角包边），所有元素坐标相对底座局部系；底座材质 / 边缘处理由 `palette.base` 决定（海崖草皮+岩层断面、松林碎石+苔藓、避难所硬化混凝土、服务区柏油+划线），但**尺寸、比例、微缩底座形式四场景统一**（1-3）。
- 构图：中央营位固定在底座视觉中心，车辆锚点统一；四周元素分「近景营位家具 / 中景结构物 / 远景剪影」三层，保证环绕观察时层次清晰且不遮挡车辆。
- 远景（山脊、城市剪影、海面、防波堤）用低多边形挤出 + 雾化处理，置于底座范围内（可略作视觉延伸，但仍在底座之上）。
- 重复元素统一走 `InstancedMesh`；共享构件从 `common/PropsLibrary.ts` 取，用参数化变体做差异。
- 每个场景模块固定导出：地形、道具布置、场景动效、色彩基调、`onTimeChange` / `onWeatherChange` 光照钩子（2.5）。

### 4.2 车型模块（逐车型）

**共性约定**

- 每个模块固定四要素（3.6）：`exterior` / `deploy`（展开机构） / `interior`（透视内饰） / `interiorLights`（内饰灯光钩子）。
- **透视可见的实现**：车窗采用大面开窗 + 低反射半透材质（避免玻璃高光遮挡），或用可见 interior 分组配合内侧补光；升顶帐帘 / 掀顶 / 尾门纱帘做成「半开」几何，保证从默认相机角度能看清内部。所有车型的内饰独立补一组暖色点光，夜间/黄昏加强。
- **细节量保障**：以 C 型为基准件数建立「内饰构件清单」，其余车型必须覆盖同等或更多件数；通过 `PropsLibrary` 共享柜体/床铺/水槽/灯具等基础件，再以配色、布局、专属道具（卫星锅、冲浪板、地图、对讲机等）形成明显差异。
- **轻微适配**：`anchor.groundOffset` / `yaw` / `scale` 统一处理接地高度与朝向；末世场景可选蒙尘涂装（通过全局 dust 参数调材质，不改车型模块）。

| 多云 | 强度 ×0.8、柔化（阴影对比降低）、饱和度 ×0.95 | 云量增加、云影在地面缓慢移动（投影平面 + 程序化云纹滚动） | 基准 | 1.3 |
| 小雨 | 强度 ×0.65、环境光 +0.1、饱和 ×0.9 | 雨丝粒子（Points + 拉伸 shader）、水洼涟漪（法线扰动）、屋檐滴水、**布料因积水微微下凹**；夜间灯光在湿地面拉出彩色反光 | `wetness=1`（roughness 降低 + 高光 + 反射色）、`clothSag=1` | 1.5 |
| 浓雾 | 强度 ×0.7、`glow` ×1.6、雾密度大增 | 远景逐层雾化、灯光扩散光晕（sprite 尺寸/透明度随雾增强）、景深层次压缩 | 远景材质雾化混合 | 0.6 |
| 降雪 | 强度 ×0.75、环境光 +0.15（雪面反光）、色温偏冷 | 雪花缓慢飘落（Points，速度低、带横向漂移） | `snow=1`（全局 Uniform 混合白色）+ `SnowCap` 上表面积雪：屋顶 / 天幕 / 树枝 / 护栏 / 桌椅顶部；地面覆薄雪（服务区划线若隐若现） | 0.8 |

**材质状态实现**：`common/SurfaceState.ts` 维护全局 `wetness` / `snow` / `dust` / `clothSag` Uniform，通过 `onBeforeCompile` 注入到共享卡通材质，避免逐物体改材质；`SnowCap` 为需要积雪的对象生成一层「上表面偏移的薄白壳」，由 `snow` 控制显隐与厚度。切换时 Uniform 在 1~2s 内渐变，粒子密度同步 0→1 渐变。

**时间 × 天气综合光照**（`weathers/modifiers.ts`，§3.4 公式）：夜间 × 浓雾 = 更暗 + 更强光晕 + 更强雾化；夜间 × 小雨 = 冷蓝紫 + 湿地面彩色灯光反光；黄昏 × 降雪 = 金橙晚霞 + 冷白雪面 + 暖灯反光；清晨 × 浓雾 = 青金晨光 + 薄雾与浓雾合并（去重，只取更强者，不重复堆粒子）。

## 5. 三渲二渲染方案

### 5.1 卡通材质与渐变色阶

- 主体用 `MeshToonMaterial` + `gradientMap`：`TextureFactory` 用 `DataTexture` 生成 **3~5 阶**色阶（`NearestFilter`），形成日式动画干净块面感。
- 每个场景的 `palette.ts` 定义一套调色板（暗部偏冷 / 亮部偏暖、描边墨色、底座色、点缀色）；时间只调制光照与曝光，天气只调制饱和度与明度，**不破坏场景固有色基调**。
- 材质层次分五类：哑光主体（toon）、半光木纹/布面（toon + 程序化贴图）、发光体（emissive + 光晕 sprite）、透明玻璃（低反射半透）、水面（定制 shader 波光）。层次「细腻但简洁、表现干净」（1-2）。

### 5.2 描边

- **主方案：反面外扩壳（inverted hull）**。为需描边的网格生成共享 geometry 的描边壳，材质 `MeshBasicMaterial({ color: ink, side: BackSide })`，顶点沿法线外扩（预计算 geometry 或 `onBeforeCompile`），厚度约模型尺度的 0.6%~1.2%，随相机距离做轻微补偿保证远近粗细一致。
- 描边色统一为**深墨蓝 / 深灰褐**（非纯黑），随场景 palette 微调，避免生硬。
- **薄片 / 透明物**（天幕、帐帘、玻璃、小旗、纱帘）反壳会穿帮，改用双面材质 + 边缘线（`EdgesGeometry` / `LineSegments`）+ 深度偏置，或仅对框架描边。
- 性能：只对主轮廓网格（车身、建筑、大件道具、底座）描边，小碎件不描边；同材质描边壳合并以减少 Draw Call。

### 5.3 程序化贴图（Canvas / SVG）

`TextureFactory` 统一生成并缓存 `CanvasTexture`，全部来自 Canvas 2D 绘制或内联 SVG 字符串：木纹、草地、碎石、柏油与车位划线、波纹铁皮、锈迹、混凝土裂纹、便利店招牌文字、路牌文字、车身手绘贴纸、车窗反光、海面波光、云纹、星空、灯光光晕（径向渐变 sprite）、草地/雪面细节。所有贴图设置正确的 `colorSpace` 与 `anisotropy`，运行时生成、零外部文件、零网络请求（8-2、8-1）。

### 5.4 天空与远景

- 天空：场景内大球体（BackSide）或全屏背景平面 + 渐变 shader，由时间预设驱动 Uniform（朝霞 / 蓝天白云 / 晚霞蓝调时刻 / 星空），天气叠加云量与雾色。
- 云层：程序化半透明面片，多云时增密，云影以滚动投影纹理在地面缓慢移动（第五节第 2 点）。
- 远景（层叠山脊、山腰云带、荒废城市剪影、断裂高架桥、海面、防波堤）：低多边形挤出 + 雾化，保持在底座之上，维持「微缩陈列盒」感（1-3）。

### 5.5 光照、阴影、色彩与美术守则

- 光照：1 盏方向光（主光 + 投影）+ 半球光 + 环境光 + 若干点光（灯光道具，按时间/天气启停）；`LightingComposer` 统一合成（§3.4）。
- 阴影：`PCFSoftShadowMap`，阴影相机紧贴底座范围以换取精度；清晨长投影、白天短而清晰，由太阳角度自然产生（第四节）。
- 色彩：`outputColorSpace = SRGBColorSpace`，toneMapping 的 exposure 随时间预设调整；避免过饱和，保持柔和分层。
- **美术守则（写入自查表）**：干净、有秩序感、有生活气；末世不做写实血腥 / 恐怖；**不出现任何人物**；材质表现干净；所有组合保持日式二次元夏日旅途感（1-5、1-6、11）。

### 5.6 过渡机制汇总

| 切换类型 | 时长 | 做法 |
| --- | --- | --- |
| 时间 | 1~2s | 双预设交叉淡入淡出：光强/光色/天空 Uniform/雾/曝光/装饰物 0~1 值全部插值（第四节第 5 点） |
| 天气 | 1~2s | 粒子密度、wetness/snow/clothSag Uniform、光晕强度、风力、光照修正系数全部插值（第五节第 6 点） |
| 场景 / 车型 | 0.4~0.6s | 淡出 → 卸载旧子树 → 构建新子树 → 重新应用当前时间/天气 → 淡入；可用全屏遮罩或渲染器 alpha 渐变（6-5） |
| 相机 | 全程 | `OrbitControls` 实例全局唯一，切换只换 `root` 下的子树，**不改 camera / target / spherical**，保持连续（6-5） |

### 5.7 性能策略（8-3，目标中端笔记本 60fps）

- `InstancedMesh` 覆盖：松树、礁石、集装箱、行道树、桌椅、沙袋、轮胎、草簇、护栏立柱、串灯灯泡、星空点、车流光点。
- 共享 geometry / material、`GeoFactory` 几何缓存、按需 `build` 与 `dispose` 释放，避免 400 组合来回切换导致内存增长。
- Draw Call 预算：初稿目标 < 300；**最终实测 674**（含反面外扩壳描边与阴影 pass），60 fps 达标。小件不投影、实例化、几何缓存已落地；`mergeStatic` 静态合批已实现但为保证内容模块 `update()` 持有的对象引用安全而未启用，列为后续优化项（§11.1 如实记录）。
- `renderer.setPixelRatio(Math.min(devicePixelRatio, 2))`；阴影贴图 1024/2048 按设备档位。
- `Ticker` 分层：必要动效每帧，次要动效 10~20Hz 节流；偶发动效（海鸟 / 松鼠 / 送货小车）用低频概率触发。
- 粒子数量上限（雨/雪）按屏幕面积与设备档位封顶。

## 6. UI 与切换过渡方案

### 6.1 布局与内容

- **位置**：右侧或左下角一块竖排轻量面板（不遮挡模型主体，6-3）；顶部/角落显示当前组合标题；右下角一个极小的「隐藏 / 呼出」入口。
- **四组分段按钮**：场景（4）/ 车型（5）/ 时间（4）/ 天气（5），每组「内联 SVG 图标 + 文字」，选中态以背景色 + 细描边 + 轻微放大明确区分（6-1）。
- **组合标题**：`山间松林 · 拖挂房车 · 夜间 · 小雨` 由 `Store` 的 label 拼接自动生成（6-2）。
- **数据驱动**：面板按钮遍历四个注册表生成，新增模块自动出现在 UI（呼应 §3.5 扩展契约）。

### 6.2 视觉规范（6-3）

半透明磨砂玻璃 `backdrop-filter: blur(12~16px)` + 半透底色；圆角 12~16px；1px 细描边（低对比亮边）；柔和多层阴影；hover 位移 / 亮度 150~200ms 缓动，选中态轻微缩放与色块；配色由当前场景 palette 与时间色调做**轻微**适配（仅调整强调色，不抢模型戏）。字体用系统字体栈，图标内联 SVG，零网络请求。

### 6.3 隐藏 / 呼出（6-4、1-4）

点击入口或按 `H` 键切换：隐藏时面板与标题整体淡出，仅留一个低对比小点用于呼出；**纯观赏模式下画面无任何 HUD**。开发态自检面板（`core/Debug.ts`）仅在 dev 模式且手动开启，默认关闭，交付构建中剔除，不算 HUD。

### 6.4 切换交互细则（6-5）

- 结构性（场景/车型）：短暂淡入淡出 / 滑动过渡；期间按钮置 loading 态，快速连点只保留最后一次请求（防抖排队）。
- 参数性（时间/天气）：光照与粒子平滑过渡，不遮挡画面、不打断操作。
- 相机连续性：`CameraRig` 全局唯一，切换前后 `controls.target`、球坐标、缩放距离均不重置，用户正在拖拽的阻尼状态保持。
- 画布自适应：`ResizeObserver` / `window.resize` 更新相机 aspect 与渲染尺寸（8-5）；触屏由 OrbitControls 默认 touch 映射（单指旋转、双指缩放）。

## 12 · 穿模专项设计与实现期调整回写（v0.3 新增）

### 12.1 三重保障

| 层 | 机制 | 实现文件 | 覆盖范围 |
| --- | --- | --- | --- |
| ① 静态数据层 | 统一底座坐标系 + 分区网格 + 中央营位禁放区 `KEEP_OUT` + 实体占位声明；校验越界 / 侵入禁放区 / 格子越界 / 实体两两重叠 / 车型占位 / 提示词点名元素覆盖度 | `src/data/layouts.js`（浏览器与 Node 共用同一份数据）、`scripts/validate-layout.mjs` | 4 场景 × 5 车型 = 20 组占位，共 400 组合 |
| ② 构建期 | `ctx.layout.place(obj, id)` 把实体放到格子中心、按占位等比缩放（不侵入邻格）、底面精确贴合 `y=0`；特效对象用 `userData.noBounds` 排除，不撑大包围盒 | `src/core/Layout.ts`、`src/core/GeoFactory.ts#groundAlign` | 每个实体构建时 |

### 12.2 布局约束的关键数值

```
底座 BASE.size = 20，内界 ±9.15，顶面 y = 0，厚度 1.15
中央营位禁放区 KEEP_OUT: x[-6.5, 6.5]  z[-2.7, 4.5]
```

- `KEEP_OUT` 覆盖**所有车型**的车身 + 展开机构 + 登车梯/踏步（最大为拖挂车 `halfLength 5.8`、A 型 `deployZ 4.2`）。任何场景实体一律不得侵入，从结构上杜绝「车辆与道具穿模」这一最常见风险。
- 六个分区 `front / back / left / right / far / backFar` 全部位于底座内界内且与 `KEEP_OUT` 不相交；每区按 `cols × rows` 划格，物件用 `cell + span` 占位，几何尺寸按 `CELL_INSET = 0.86` 内缩，留 14% 间隙 → 相邻物件**必然不接触**。
- `h <= 0.06` 视为贴地装饰层（野餐垫、防水地垫、水面、车位划线、林缘地被等），允许与实体同区铺设但仍受越界与禁放区约束；不参与积雪覆盖。
- 车型包围盒上限由 `VEHICLES` 登记，运行时若超出 `halfLength + 0.25` / `deployZ + 0.25` / 高度 6.0 会报警。

### 12.3 各类穿模的具体对策

| 风险类型 | 对策 |
| --- | --- |
| 车辆 × 场景道具 | `KEEP_OUT` 禁放区 + 静态/运行时双重包围盒检查 |
| 道具 × 道具 | 分区网格 `cell + span` 内缩占位 + 两两 AABB 校验 |
| 物件悬浮 / 沉入地面 | `groundAlign()` 按真实包围盒底面精确贴合 `y = 0`；所有 PropsLibrary 构件以底面中心为局部原点（y ≥ 0） |
| 积雪薄壳与本体共面闪烁 | 独立薄壳置于顶面 `+0.018`，`polygonOffsetFactor = -2`、`depthWrite = false` |
| 描边壳与本体 z-fighting | 反面外扩壳沿法线外移 0.028~0.030，`BackSide` + `renderOrder = -1`；透明物跳过描边 |
| 玻璃遮挡透视内饰 | 低反射半透 `depthWrite = false` + `polygonOffset`，配合车内独立点光补光 |
| 布料摆动穿过支架 | 振幅上限 0.16、`centerFalloff` 中心衰减、小雨下凹走 `clothSag` 而非增大摆幅 |
| 实例化散点越界 | `contentBox()` 逐实例应用 `instanceMatrix` 计算真实包围盒，避免只算单个原型而漏判 |
| 光晕 / 光束撑大包围盒 | `glowSprite()` 内置 `userData.noBounds = true`；光束、大背景面片同样标记并直接挂根，不参与占位与缩放 |
| 车辆内部家具互插 | 统一车身坐标系与内饰分区（贴墙布置、留中央通道），由 `VEHICLES` 占位上限兜底 |

### 12.4 实现期设计调整（回写基线）

| 项 | 初稿（§3.5） | 实际实现 | 原因 |
| --- | --- | --- | --- |
| 注册表装配 | 「新增模块 + 注册一行」 | `registry/index.ts` 用 Vite `import.meta.glob` **自动发现** `scenes/*/index.ts`、`vehicles/*/index.ts`、`times/*.ts`、`weathers/*.ts` 并 default export 注册；新增模块**连一行注册代码都不用写** | 更彻底地满足 2.5 / 3.6「核心零改动」；辅助文件无 default export 会被自动忽略，`_template` 目录按路径过滤 |
| 结构性切换 | 场景与车型分别重建 | `rebuildAll(scene, vehicle)` **一起重建** | `DecorController` 的 `bind` 是场景与车型共用的；只重建其一会丢失另一方的灯光/装饰订阅。在淡出遮罩下重建，用户无感 |
| 贴地层 | 所有实体严格互斥 | `h <= 0.06` 的贴地装饰层豁免两两重叠检查 | 水面、地垫、车位划线本就铺在地面，不构成穿模 |
| 依赖版本 | 「安装时锁定」 | Vite **7.3.8** + TypeScript **5.9.3**（而非最新的 Vite 8 / TS 7）；three 0.187.0 | 规避新版本工具链兼容不确定性；详见 `DEPENDENCIES.md` §2 |
| pnpm 12 构建脚本 | 未预见 | `pnpm-workspace.yaml` 增加 `allowBuilds: esbuild: true` | pnpm 12 默认拦截 esbuild 的 install 脚本（`ERR_PNPM_IGNORED_BUILDS`），按白名单放行，未做任何删除操作 |

## 附录 A · 命名与代码规范

- 模块 id 使用小写驼峰：`seaCliff` / `typeC` / `dusk` / `clear`；显示名用中文 label。
- 注册表只做「登记 + 查询」，不含业务逻辑；UI 遍历注册表生成按钮。
- 核心层禁止 import `scenes/` / `vehicles/` / `times/` / `weathers/` 下的具体模块。
- 所有几何与贴图必须有创建与释放配对；切换场景/车型时 `dispose()` 必须被调用。
- 每个模块必须有 `update(dt, env)` 入口（无动效则留空实现），保证 `Ticker` 统一调度。
